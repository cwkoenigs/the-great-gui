# AGENTS.md

A native Mac manager for Clark's terminal commands, drawn with the ds-next terminal design system.
Swift package (TerminalDesign, Registry, Runner, Secrets, GreatGUI); VS Code; builds with the command-line tools alone.

- Build: `swift build` · Test: `swift test` · Check: `make check` · App: `make app` · Look: `make snapshot` (draws the window's screens off screen; the sidebar's rows and glass controls do not draw)
- One look (DECISIONS local-032): the native window in `Sources/GreatGUI/Modern`. The terminal look and the gallery are gone; do not bring them back. `Sources/TerminalDesign` stays for the colour roles, the mono face and the embedded terminal's palette.
- `Sources/TerminalDesign/Tokens.swift` is generated: change canon's terminal design export, then `make tokens`.
- Two themes fill the colour roles (DECISIONS local-026): `dsNext`, which with the dark appearance is what a Mac starts in (DECISIONS local-040), and `paperInk` (Paper and Ink), kept by hand in `Sources/TerminalDesign/PaperInk.swift`. One visual language (DECISIONS local-036): a view takes its shapes, selection, fields, tabs, chips and table rows from `Palette` and `Modern/Kit.swift` (`heading`, `kicker`, `sectionLabel`, `pill`, `panel`, `codeBlock`, `primaryButton`, `secondaryButton`, `selected`, `fieldBox`, `LabeledField`, `formSection`, `SheetFrame`, `Screen`, `HeaderRow`, `tableRow`, `Tabs`, `chip`, `rowAction`, `NoteLine`, `EmptyState`). Never a literal corner radius, capsule or glass effect in a view, never a system `Table`, a grouped `Form`, a segmented picker or the system's list selection. A new screen is a `Screen`; a new sheet is a `SheetFrame`.
- The web kit in canon (`terminal-design/design-system/components/terminal/*.jsx`) is the reference for every primitive's look.
- A model built for a test or a snapshot takes `Snapshot.inertScheduler(in:)`, a throwaway `SecretStore` service and `watch: false`. A model with the default scheduler syncs the real launchd agents to whatever registry it loads, and would delete every agent that registry does not name.
- No `@State` (DECISIONS local-006): view state lives in `@Observable` / `ObservableObject` models under `@StateObject`.
- The repository is public (DECISIONS local-041): never name an employer, a work product, a work host or a path on a work machine in code, a doc or a commit message.
- Ask Clark before adding a dependency, changing the macOS floor, the bundle identifier or the signing setup.
- Schedules are launchd agents written by `Scheduler.sync` from the registry's `schedule` phrases; never hand-write a LaunchAgent for a command, and keep the folders and labels behind their `GREAT_GUI_*` overrides so a test instance stays apart from the real agents.
- Adding, editing, removing and reordering a command go through `RegistryWriter` only (`append`, `replace`, `remove`, `reorder`): the ⌘N/⌘E form, `great-gui add|edit|remove` and the `add-command` skill. It rewrites one block and keeps the rest of the file; never regenerate the whole file. The registry format is in README; `Registry.parse` must stay loud about mistakes (strict keys, named fixes).
- Decisions go in `DECISIONS.md` (ds-next's format). Secrets never go in the registry, the history, a log or a message. Values are read in two places only: `RunEnvironment.build` (a run's environment, for the window and `great-gui run`) and `FileSecrets` (a whole file, between its Keychain item and its path); neither returns a value to a view.
- To use a stored credential yourself, follow `skills/use-secret`: `great-gui secrets` for the names, `great-gui exec --env KEY=keychain:NAME -- …` to run with one. Never ask for, read or print a value. Every path that prints a command's output on the command line goes through `CLI.runMasked`.
- Agents are the main users of the command line (docs/team-tooling.md). Every command takes `--json` (add it to `CLI.reporting`, answer with exactly one `CLI.emit`; under `--json` nothing else may reach stdout, so a run's own output goes to stderr), reports errors through `CLI.fail`, and keep the exit codes: 0 fine, 1 not as it should be, 2 wrong or refused, 10 update waiting.
- The team's registry (DECISIONS local-027, `Sources/Registry/Team.swift`, `Sources/GreatGUI/Model/TeamSync.swift`) is a second `commands.toml` in `~/.great-gui-team`, cloned from an address the person gives. Read with `Registry.loadAll`; write only the person's own file (`Registry.load(from:)` plus `RegistryWriter`). Never write, commit or push in the team folder, never arm a team schedule, and never hard-code a git host: the address lives in the clone's remote.
- Tools (DECISIONS local-028, `Sources/Registry/Tools.swift`, `ToolRunner`, `CLI+Tools.swift`) are `[[tool]]` entries, the person's and the team's. A look (`ToolProbe.script`) asks package managers and PATH only; the daily one passes `versions: false` and must never execute a line or a program a registry names. Install and update run only when asked: a button, or `great-gui tools install|update`. Never install from a sync. When testing, use `script` tools whose lines are `echo`: a real `brew` or `uv` entry changes this Mac.
- Secret values never leave the Mac they were stored on: no export, import, sync or cloud backend for secrets or `[[file]]` contents, ever. Only the pointers travel; keep `path` written with `~`.
